# Publish one Agent Plugin as the portable distribution of the native agent integration

OKF Harness publishes one standards-conforming Agent Plugin at `plugins/agent-plugins/okf-harness/` as the portable distribution of its native agent integration (#131, #133): one package any agent client that loads Agent Skills and runs local shell commands with npx access can install, including Codex through the unchanged `okf-harness@okf-harness` marketplace entry. The host-specific Claude Code and Codex packages keep their native install surfaces.

The renderer's host-skill target is a distribution target (#134): one shared template set renders the host-specific variants and the portable variant, and only the substitutions differ. The portable variant carries no client identity — no agent metadata key and no client name in its frontmatter, with distribution recorded as `okf-harness-distribution: portable` — and its description keeps the per-host trigger words and exclusions verbatim, because description is the only text loaded at startup and the same request must route identically no matter where the person installed from. The installable host set that drives host-level entrypoint installation, host detection, and doctor stays exactly as it is: the portable target renders, it never installs, keeping the ADR 0044 and ADR 0045 mechanisms untouched.

The setup and repair references determine the `--agents` target by self-report: Claude Code and Codex map to those adapters, and any other client maps to `--agents none`. No heuristic guessing — a wrong guess writes workspace-local guidance that misleads every later session, while `none` can always be repaired afterwards. Because `agent install` accepts no `none` target, the repair route reports that an unrecognized client has no workspace-local guidance to install and falls back to daily routing.

The package version is locked to the root package version, and the package's agent-facing files equal a fresh render of the portable target, both asserted by the artifact test. Universal setup and doctor are unchanged. Compatible clients outside the supported agent set follow the documented manual install paths, receive no ADR 0044 level and no recurring verification obligation, and are never updated by any OKF Harness installer.

Consequence: a Codex user who installs through the marketplace now receives the portable skill variant, while universal setup's host-level entrypoint install keeps rendering the Codex variant. The trigger surface is identical by construction; the differences are the removed client name, the distribution metadata, and the self-report determination of the `--agents` target.
