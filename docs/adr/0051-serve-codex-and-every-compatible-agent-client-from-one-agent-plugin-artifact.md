# Serve Codex and every compatible agent client from one Agent Plugin artifact

OKF Harness serves Codex and every other agent client conforming to the Agent Plugins standard from one artifact: the standards-conforming Agent Plugin at `plugins/agent-plugins/okf-harness/`, upgraded in place from the former Codex package rather than created as a second, parallel package (#131). Codex CLI reads Agent Plugins manifests natively, so the Codex-private shape yields to the standard shape in place and one directory serves every compatible client. This supersedes the earlier prototype direction of a portable directory beside the per-host directories (#121), made before Codex's native support for the standard was known.

No parallel package is needed: the artifact behind the Codex marketplace entry is the artifact every other client installs, and a second package would only duplicate it. No migration is asked of any user: the marketplace entry, its storefront, and the install identifier `okf-harness@okf-harness` do not change, and already-installed Codex users keep their installed copy.

The package stays in a subdirectory rather than at the repository root: a manifest at the root would force the repository's own host-level entrypoint skill and the distributed skill to merge into one, and those are different artifacts today — merging them is a separate effort. Distribution is by the main repository's git contents only, consistent with ADR 0040: no new npm package, because the standard defines no registry and every real install path points at a directory. The package version is locked to the root package version, as is the skill's version metadata; version bumps remain release work.

Universal setup and doctor are not modified in their install surfaces; their executable lookup is shared through the host-probe module (ADR 0052), which precedes this convergence. Codex already receives this artifact through the unchanged marketplace path, and offering installs for clients outside the supported agent set would amount to claiming support for them.

Any client conforming to the standard can install the package by hand while staying outside the supported agent set: it receives no level under ADR 0044, and the verification obligation is explicitly zero — no release check and no recurring recipe audit; anyone who tests a client updates that client's documented evidence status in the install page by ordinary pull request. A hand-installed package is never updated by any OKF Harness installer; its version metadata is what an agent inspects to judge staleness. The documented manual install paths live in `docs/AGENT-PLUGIN.md` (#135).

Two points surfaced only when the decisions met the code. The name collision an earlier prototype exposed — one repository publishing two packages under one name — disappears rather than being resolved: after this convergence there is still only one Agent Plugin. And a Codex user who installs through the marketplace now receives the portable skill variant, while universal setup's host-level entrypoint install keeps rendering the Codex variant (ADR 0050); the trigger surface is identical by construction, and only the removed client name, the distribution metadata, and the self-report determination of the `--agents` target differ.

ADRs 0039, 0040, 0044, and 0045 stay untouched, including their index rows. ADR 0045's statement that Claude Code and Codex install `okf-harness@okf-harness` from the main-repository marketplace remains literally true: what changed is the artifact behind the entry, not the identifier. Marking it superseded would tell a reader that the Codex install path changed, which is the one thing that did not happen — the identifier surviving a full change of package shape is evidence that the abstraction was cut in the right place.
